# API: отметки прочтения комментариев

Модалка «кто и когда видел комментарий» + точка старта ленты на первом
непрочитанном.

Хранится не отметка на каждый комментарий, а **водяной знак**: одно число на
пару (карточка, пользователь) — докуда человек дочитал. Знак только растёт.
Бэкенд не решает, что считать прочитанным: он принимает число, которое прислал
фронт.

Все эндпоинты — под тем же JWT, что и остальной канбан. Ошибки в общем формате:

```json
{ "error": "card_not_found", "code": "card_not_found" }
```

---

## 1. Отметить прочитанным

```
POST /spa/api/kanban/cards/{cardId}/comments/read
```

**Тело:**

```json
{ "lastCommentId": 47 }
```

**Ответ:** `204 No Content`, без тела.

Идемпотентен и безопасен к повторам: меньшее или равное число ничего не меняет.
Комментарий должен существовать, быть живым и принадлежать этой карточке —
иначе запрос молча не делает ничего (всё равно `204`). Прислать id «из
будущего», чтобы пометить прочитанными ещё не написанные комментарии, нельзя.

**Ошибки:**

| Статус | `code` | Когда |
|---|---|---|
| 400 | `validation_failed` | `lastCommentId` отсутствует или ≤ 0; `cardId` не число; карточка — подзадача |
| 400 | `invalid_json` | тело не парсится |
| 401 | `unauthorized` | нет пользователя в токене |
| 403 | `access_denied` | нет доступа к проекту |
| 404 | `card_not_found` | карточки нет |

## 2. Кто видел комментарий

```
GET /spa/api/kanban/cards/{cardId}/comments/{commentId}/readers
```

Запрос под модалку, по клику. Дёргать на каждый комментарий в ленте не нужно.

**Ответ `200`:**

```json
{
  "readers": [
    {
      "user": {
        "id": 144,
        "login": "ivanov_ii",
        "lastname": "Иванов",
        "firstname": "Иван",
        "patronymic": "Иванович",
        "avatarName": "avatar_144.jpg"
      },
      "readAt": "2026-09-12T09:15:00Z",
      "readBeforeEdit": false
    }
  ],
  "pending": [
    {
      "id": 145,
      "login": "petrov_pp",
      "lastname": "Петров",
      "firstname": "Пётр"
    }
  ]
}
```

- `readers` — кто видел, **отсортированы по времени**, первым тот, кто увидел раньше
- `pending` — участники проекта, которые ещё не видели, **по фамилии**
- `patronymic` и `avatarName` могут отсутствовать
- автор комментария не попадает ни в один список
- оба массива всегда присутствуют, пустой список — `[]`
- `readAt` сериализуется так же, как `createdAt` у комментариев — тот же тип
  колонки и тот же путь наружу, секунды без долей

### `readAt` — что это за время

Момент захода, в который человек впервые оказался «дочитавшим» до этого
комментария. Если он открыл карточку и разом получил 20 новых комментариев —
у всех двадцати будет одно и то же время. Это не округление, а факт: он
действительно увидел их одновременно.

### `readBeforeEdit`

`true`, если комментарий правили **после** того, как этот человек его прочитал —
значит он видел другую формулировку. Показывать подписью вроде «изменён после
прочтения», иначе отметка легко оспаривается.

**Ошибки:**

| Статус | `code` | Когда |
|---|---|---|
| 400 | `validation_failed` | `cardId`/`commentId` не число; карточка — подзадача |
| 403 | `access_denied` | нет доступа к проекту |
| 404 | `card_not_found` | карточки нет |
| 404 | `comment_not_found` | комментария нет, он удалён или принадлежит другой карточке |

## 3. Точка старта ленты

В ответ карточки добавлено поле `lastReadCommentId`.

`GET /spa/api/kanban/cards/{id}` — поле на верхнем уровне:

```json
{
  "id": 10,
  "comments": [ ... ],
  "commentsCount": 8,
  "lastReadCommentId": 5
}
```

`GET /spa/api/kanban/cards/{id}/standalone` — то же поле **внутри `card`**:

```json
{
  "card": {
    "id": 10,
    "comments": [ ... ],
    "commentsCount": 8,
    "lastReadCommentId": 5
  },
  "projectId": 26,
  "columns": [ ... ]
}
```

`lastReadCommentId` — докуда дочитал **текущий** пользователь. `0` означает, что
карточку ещё не открывали. Число живёт на сервере, поэтому точка старта
переживает смену устройства и браузера.

Непрочитанные — это комментарии из `comments` с `id > lastReadCommentId`.
**Не вычитать числа:** `commentsCount - lastReadCommentId` даст ерунду,
потому что удалённые комментарии оставляют дырки в id. Считать по массиву.

---

## Порядок на фронте

1. Открыли карточку → взяли `lastReadCommentId` из ответа.
2. **Сначала** прокрутили ленту к первому комментарию с бо́льшим id.
3. **Потом** отправили `POST .../comments/read` с id последнего комментария.

Если поменять шаги 2 и 3 местами, точка старта затрётся до того, как ею
воспользовались, и лента всегда будет открываться в конце.

### Что означает галочка

Сейчас отметка ставится по факту открытия, значит она означает **«открывал
карточку»**, а не «прочитал». В интерфейсе подписывать соответственно —
«Открывали», не «Прочитали». Разница важна: пользователи собираются ссылаться
на эти отметки в рабочих спорах.

Когда понадобится честная отметка — `IntersectionObserver` на комментариях,
выдержка ~1 секунда, полная видимость, отправка максимума раз в 2–3 секунды и
флаш при закрытии карточки. **Бэкенд при этом не меняется**: он как принимал
одно число, так и принимает.
